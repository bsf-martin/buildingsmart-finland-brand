Medium-Specific Rules
Web & HTML documents
  • Figtree — all headings H1–H6, UI elements, labels, navigation.
  • Source Serif 4 — all running body text. Italic for pull quotes and callouts.
  • Load via Google Fonts CDN — no local font dependency for readers.
PowerPoint presentations
  • Figtree carries all slide text including body. Minimum 18pt — no exceptions.
  • Source Serif 4 italic — callout boxes and pull quotes only. Never upright on slides.
  • Fonts are embedded in the template. Users must also install fonts locally to edit.
Word documents (.docx)
  • Figtree — all headings H1–H6 via named paragraph styles (27pt → 10pt). Never manual size overrides.
  • Source Serif 4 — Normal style for body text at 12pt. Italic for emphasis and pull quotes.
  • Caption style at 10.5pt; JetBrains Mono character style at 10pt for inline identifiers.
  • Fonts must be installed on the authoring machine. The .dotx template does not embed fonts.
JetBrains Mono — all media
  • IFC schema names, file extensions, version strings: IFC4.3 IfcWall BCF 3.0
  • Never for decorative use. Arial, Calibri, and Times New Roman are forbidden in all distributed materials.

Components · 07

Code Blocks

Inline code for identifiers within running text; block code for schema fragments, snippets, and structured data. Both use JetBrains Mono.

Inline Code

The IfcWall entity inherits from IfcBuildingElement. Use Pset_WallCommon to attach common properties defined by IFC4.3.

Block Code — Navy background
// IDS requirement — IfcWall must carry Pset_WallCommon "applicability": { "entity": { "name": "IfcWall" } }, "requirements": { "property": { "propertySet": "Pset_WallCommon", "name": "IsExternal", "dataType": "IfcBoolean", "minOccurs": 1 } }
Guidance · 01

Do / Don't

Four rules that protect the system's integrity. Each violation erodes the clarity and distinction the palette and type system are designed to create.

Rule 1 — One accent per composition
✓ Do
IFC4.3 Released

The latest version of the IFC schema introduces significant improvements to infrastructure modelling.

Single Mint element — the CTA button. Everything else is Navy and Charcoal.
✗ Don't
IFC4.3 Released

The latest version of the IFC schema introduces significant improvements to infrastructure modelling.

Mint heading + Mint button. The accent loses its power when it appears twice.
Rule 2 — Figtree and Source Sans 3 only
✓ Do
Open BIM Standards

Interoperability begins with a shared language for building data.

Figtree heading + Source Sans 3 body — the correct pairing.
✗ Don't
Open BIM Standards

Interoperability begins with a shared language for building data.

Arial heading + Times New Roman body. System fonts are forbidden in all distributed materials.
Rule 3 — Use approved colour pairings only
✓ Do
Section label

Charcoal (#38363D) on white: 11.5:1 contrast ratio.

Charcoal on white passes AAA (11.5:1). Slate passes AAA for the label (9.1:1).
✗ Don't
Section label

Silver (#C8C6C5) on white: 1.7:1 — fails all WCAG criteria.

Silver on white fails WCAG (1.7:1). Silver is for borders and dividers — never for text.
Rule 4 — Mint is an accent, not a surface
✓ Do
Active ACTIVE STATE
Mint as a small tag, active indicator, or dot. Contained, purposeful.
✗ Don't

Body text on a full Mint background panel.

Mint as a large background surface. It overwhelms the composition and reads as decorative, not purposeful.
